✓ AFTER : STRUCTURED AGILE SPRINT BLUEPRINT
Establish the SDLC framework for the CareConnect EHR engineering initiative: 1. Methodology: Adopt Agile Scrum with 2-week sprint cycles combined with Stage-Gate healthcare compliance checkpoints. 2. SDLC • 02 User Story Mapping & INVEST Criteria
Page 2 of 5
✗ BEFORE : INFORMAL / UNPLANNED EXECUTION
"doctor ke liye features likho jo unhe chahiye"
SDLC Bottleneck / Risk: Unstructured Scope: Vague feature requests lack user roles, acceptance criteria, testability, and cannot be estimated or tracked in sprints.
✓ AFTER : STRUCTURED AGILE SPRINT BLUEPRINT
Author production-grade User Stories adhering to the INVEST standard (Independent, Negotiable, Valuable, Estimable, Small, Testable): 1. User Story Format: 'As a , I want so that ' - Example: 'As a Physician, I want the system to warn me if I prescribe Aspirin to a patient taking Warfarin, so that fatal bleeding complications are prevented.' 2. Acceptance Criteria (Gherkin Given-When-Then syntax): - Given a patient with active Warfarin prescription, - When the doctor submits an order for Aspirin, - Then display a CRITICAL safety alert modal and require clinical override justification. 3. Definition of Done (DoD): Code complete, unit tests > 80% coverage, PR reviewed, and deployed on staging.
Agile & Planning Gains: Transforms informal feature ideas into measurable INVEST user stories with Gherkin acceptance criteria and a strict Definition of Done.

SDLC • 04 Sprint Velocity, Story Estimation & Capacity Planning
Page 4 of 5
✗ BEFORE : INFORMAL / UNPLANNED EXECUTION
"kaam kitne din me hoga sab developers ko kaam assign kr do"
SDLC Bottleneck / Risk: Overcommitting & Burnout: Assigning arbitrary deadlines without velocity baselining or story point estimation leads to missed delivery dates and technical debt.
✓ AFTER : STRUCTURED AGILE SPRINT BLUEPRINT
Implement Fibonacci-based Agile Estimation and Capacity Planning: 1. Estimation Method: Planning Poker using modified Fibonacci scale (1, 2, 3, 5, 8, 13) evaluating complexity, uncertainty, and effort. 2. Team Capacity Calculation: 4 developers x 8 days effective focus time = 32 dev-days (~36-40 velocity points per sprint). 3. Spike Stories: Allocate maximum 5-point timeboxed spikes for complex unknowns (e.g. evaluating LOINC library parsing vs custom enum). 4. Buffer Strategy: Reserve 15% sprint capacity for bug fixes, code reviews, and unplanned production hotfixes.
Agile & Planning Gains: Prevents overcommitment through Fibonacci story point estimation, empirical velocity tracking, and allocated engineering buffer time.

SDLC • 05 Continuous Inspection & Sprint Retrospectives
Page 5 of 5
✗ BEFORE : INFORMAL / UNPLANNED EXECUTION
"sprint khatam hone ke baad agla sprint chalu kro bina kisi meeting ke"
SDLC Bottleneck / Risk: Recurring Process Inefficiencies: Skipping retrospectives prevents teams from identifying technical bottlenecks, compounding delivery friction over time.
✓ AFTER : STRUCTURED AGILE SPRINT BLUEPRINT
Structure the Sprint Retrospective and Continuous Inspection mechanism: 1. Retrospective Framework: 'What went well', 'What caused friction', 'Actionable commitments for next sprint'. 2. Key Metrics Tracked: - Sprint Burndown & Velocity consistency. - Defect Escape Rate (bugs found post-merge). - PR Cycle Time (time from PR open to merge). 3. Action Item Ownership: Each retrospective must produce no more than 2 high-impact process improvements with dedicated engineer ownership. 4. Continuous Improvement: Re-evaluate testing bottlenecks and CI pipeline latency to continually shorten feedback loops.
Agile & Planning Gains: Introduces continuous process inspection, defect tracking metrics, and actionable sprint-over-sprint workflow optimizations.
